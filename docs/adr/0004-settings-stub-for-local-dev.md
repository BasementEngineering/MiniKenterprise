# Local Settings stub for offline dev/testing

The Settings page's `/api/settings` GET/POST calls have no backend when running `npm run dev`, blocking local iteration on layout and save/load behavior before flashing hardware. We considered proxying to a real device on the LAN (requires hardware always on hand) and a client-side fetch mock inside `settings.js` (duplicates protocol parsing into production code). Instead we added a small standalone dev-only Node script (`minikenterprise_frontend/settings-stub.js`) that fakes the same `key=value` wire protocol from an in-memory object, proxied via Vite. It mirrors the protocol shape only, not EEPROM storage or restart semantics, so it's a test double alongside the real `Settings` (ADR 0002), not a second implementation of it.
