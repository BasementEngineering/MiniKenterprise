# Flat EEPROM struct for runtime settings, not Preferences/LittleFS/JSON

Duck (a sibling project sharing this firmware base) built a `Preferences`-backed, JSON-schema-driven settings system supporting pluggable per-motor driver types — flexible, but the kind of "support every hardware variant" complexity that previously made this codebase hard to maintain. Mini Kenterprise's settings are deliberately scoped down to what builders actually asked for: WiFi credentials and named pin numbers, nothing pluggable. We're storing this as one fixed-size struct via the ESP8266 core's EEPROM-emulation library, validated with a magic byte, with no JSON library or filesystem involved. If a genuine need for per-hardware-variant driver configuration reappears, that's a separate future decision, not something to bolt onto this struct.
