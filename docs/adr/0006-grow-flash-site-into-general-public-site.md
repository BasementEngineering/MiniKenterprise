# Grow flash-site into the general public site, not a separate configurator project

Builders now need to pick a bottle size, driver, motor and prop before they can get a correct BOM and STL set — a real feature (the Configurator), not a documentation tweak. We're adding it as `configure.html` inside the existing `flash-site/` directory, alongside a new `flash.html` and a chooser `index.html`, rather than starting a second static site or repo. `flash-site/` was already a GitHub Pages target with its own publish workflow, its own "no build step" convention, and its own stylesheet — reusing all three means one Pages workflow, one link from the root `README.md`, and one place a builder lands regardless of which of the two things (flash vs. configure) they came for. The cost is that `flash-site` becomes a mild misnomer — it's no longer just the flashing page — and its `flash-site/**`-triggered deploy now couples releases of two previously-unrelated concerns (firmware distribution and parts/print selection). We're accepting that cost rather than renaming the folder or splitting the deploy pipeline; the folder keeps its name.
